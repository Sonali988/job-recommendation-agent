# Units of Work — Dependency Matrix

**Units**: U1 (Frontend SPA), U2 (Backend: FastAPI incl. MCP mock + seed data + case model).

---

## Inter-Unit Dependency Matrix

| From \ To | U1 Frontend | U2 Backend | Amazon Bedrock | Browser localStorage |
|---|---|---|---|---|
| **U1 Frontend** | — | HTTP/JSON (ApiClient → REST) | none (never direct) | Web Storage API |
| **U2 Backend** | none | — | boto3 / HTTPS | none |

- **U1 → U2**: runtime dependency over HTTP/JSON. Contract = U2's OpenAPI schema (Q4=A). U1's ApiClient is typed manually against it.
- **U2 → Bedrock**: runtime dependency via boto3; credentials/model/region from env; explicit timeouts.
- **U1 → localStorage**: session persistence only; never touches disk seed JSON.
- **No build-time coupling** between U1 and U2 (Q3=A: independent types, seed JSON as the shared data contract).

---

## Build & Development Dependencies
- U2 has **no dependency** on U1 → can be built and run standalone (with its OpenAPI docs).
- U1 depends on U2's **API contract** (not its code). During dev, U1 can run against the live backend or a mock matching the OpenAPI shape.
- **Build order (CONSTRUCTION)**: U2 first (contract ready), then U1. Integration verified in Build and Test.

## Shared Contracts
- **Data contract**: seed youth-case JSON shape (mirrored by TS interfaces in U1 and Python models in U2).
- **API contract**: OpenAPI generated by FastAPI (U2) — the reference U1 targets.

## Trust Boundary
- The single trust boundary is the U1↔U2 HTTP channel. Secrets (AWS credentials) live only in U2 (env). U1 bundles contain no secrets (US-10.1).

## Coupling Notes
- Loose coupling: U1 and U2 evolve independently as long as the OpenAPI contract holds.
- Within U2, the MCP tool interface and AIClient are behind protocol interfaces (DI, Q9 from application design) so they remain swappable even though they live in the same unit.
